# Schema Migration Manifest

Phase 110 fixes the migration manifest structure that follows the Phase 109 schema versioning rules. The goal is to make breaking or index-affecting changes explicit before any runtime, dashboard, API, or domain-pack code silently changes a contract.

## Contract Shape

The migration manifest ledger is generated by:

```bash
npm run contracts:migrations
```

It writes:

- `artifacts/schema-migration-manifest/latest/schema-migration-manifest-ledger.json`
- `artifacts/schema-migration-manifest/latest/migration-manifest-schema.json`
- `artifacts/schema-migration-manifest/latest/core-migration-manifest.json`
- `artifacts/schema-migration-manifest/latest/pack-migration-manifest.json`
- `artifacts/schema-migration-manifest/latest/index-migration-manifest.json`
- `artifacts/schema-migration-manifest/latest/migration-records.json`
- `artifacts/schema-migration-manifest/latest/validation-report.json`
- `artifacts/schema-migration-manifest/latest/summary.md`

## Migration Tracks

The ledger separates three tracks:

- `core`: bridges legacy or breaking control-plane contract changes, including legacy schemas that Phase 109 allowed only as contained exceptions.
- `pack`: tracks domain-pack compatibility metadata and pack manifest evolution without requiring core code changes.
- `index`: rebuilds derived surfaces such as contract inventory, dependency maps, dashboard sources, and API route indexes.

Each track must declare data migration steps and index migration steps separately. A track also needs a dry-run command, rollback note, validation command, dependency list, and immutable migration record.

## Gate Expectations

P110 is complete only when:

- Phase 109 schema versioning rules are complete.
- Core, pack, and index migration manifests are all declared.
- Every manifest has a matching migration record.
- Data migration and index migration steps are not collapsed into one list.
- The legacy `matter` and `dev-projects` schema exceptions are covered by the core migration.
- Dashboard, Review API, goal checkpoint, and control-plane loop can all see the migration ledger.
