# Product and Domain SaaS Factory

P6201-P6600 turns Hermes into a control factory for multiple SaaS development efforts.

Command:

```bash
npm run platform:product-domain-saas-factory -- --check
```

Hermes does not become the HR SaaS, the law-firm SaaS, or any single vertical product in this phase. Hermes remains the governance harness around those projects.

## Factory Review Process

Every factory project uses the same milestone review lane:

```text
Codex implementation packet
Harness deterministic validation
Claude Code Opus max independent review receipt
Finding loop and revalidation
Receipt registration
Single-owner trust classification
```

Human adjudication is excluded from the current milestone gate. Therefore the factory can register control plans and lower-trust readiness, but it cannot claim protected final approval, product launch authority, enterprise trust, runtime execution, write action, or Work OS production maturity.

## Registered Control Plans

The first factory contract registers:

- `project.hr_solution_internalization`
- `project.law_firm_os`
- `project.hermes_harness`
- `project.zendd_bridge`

Each project requires requirement source binding, phase progress, evidence registry, transcript source binding, review process binding, blocker status, and next allowed action before any release claim can be considered.

## Domain Packs

The factory registers these domain packs as `CONTROL_PLAN_ONLY`:

- `personal-dev`
- `law-firm`
- `creative-document`
- `connectors-resource`
- `trading-read-only`

Control-plan only means no runtime execution, no product writes, no protected action, no raw sensitive data ingestion, and no launch.
