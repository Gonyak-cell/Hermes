# S0-4. 소유자 판정 — 병합 거버넌스 (181커밋 백로그)

> 지위: **OWNER ADJUDICATED** / 2026-06-11 / 초안 작성: Fable 5 (`claude-fable-5[1m]`) / 판정 반영: Codex
> 본 문서는 사용자의 명시 지시("전부 권고안대로")에 따른 human owner 판정 기록이다.

## 1. 문제

- `codex/p3840-review-hardening`이 `main`(tip `f3b2ca7`, 2026-06-04 정지)보다 **181커밋 앞**.
- phase 번호가 붙은 모든 작업이 미병합 — "통제형 리포 쓰기 레인"을 만들려는 저장소 자신의
  가장 즉각적이고 구체적인 쓰기 거버넌스 문제가 바로 이 백로그다.
- FCORE 작업이 어느 브랜치에 적재되는지도 이 판정에 의존한다.

## 2. 선택지

### 선택지 A — 일괄 합류 후 시작

소유자 검토 1회로 현 브랜치를 main에 합류(merge 또는 squash)시키고, FCORE는 main에서 시작.

- 장점: 단순, 기준선 명확. 단점: 181커밋 일괄 검토는 HRM-03 정신(≤25커밋 윈도우)과 정면 충돌 —
  사실상 무검토 합류가 된다.

### 선택지 B — 현 브랜치 작업 트렁크 선언

현 브랜치를 작업 트렁크로 선언하고 main을 동결 레거시로 둔다. FCORE는 현 브랜치에서 진행.

- 장점: 즉시 진행 가능. 단점: 백로그 문제를 영구 이연, "main = 신뢰 기준선" 의미 상실.

### 선택지 C — 팩토리 첫 파일럿으로 처리 (권고)

**Hermes 자신의 병합 프로세스를 파일럿 1의 대상으로 삼는다** ([06-pilot-strategy.md](../06-pilot-strategy.md) 파일럿 1).
즉시 조치로는 B(현 브랜치에서 FCORE 진행)를 취하되, Stage 3~5에서 후보 diff 패킷 단위
(≤25커밋 묶음)로 백로그를 영수증 게이트 합류시킨다. 백로그 합류 자체가 G1b의 첫 실증이 된다.

- 장점: 실제 문제로 팩토리를 검증 (dogfooding), HRM-03 정합, 백로그가 자산이 됨.
- 단점: main 합류 완료까지 시간 소요 (Stage 5 이후).

## 3. 부수 규칙 (어느 판정이든)

1. FCORE 커밋은 현 브랜치(또는 그 자식 브랜치)에 적재하며 phase=커밋 1:1을 유지.
2. main 직접 push 금지. 합류는 항상 검토 가능한 묶음 단위.
3. 본 패키지 문서의 커밋은 구현 커밋과 분리.
