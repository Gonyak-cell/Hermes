## Scope

G1a owner receipt intake validates a future signed owner
`receipt_kind: gate_opening` receipt before the isolated source-literal opening
commit can be prepared.

```bash
npm run factory:g1a-owner-receipt-intake
npm run factory:g1a-owner-receipt-intake -- --check
node scripts/review-api.mjs --once /api/factory/g1a-owner-receipt-intake
```

The current default receipt is still the unsigned template generated by
[g1a-opening-packet.md](g1a-opening-packet.md), so the intake status is
`waiting_for_signed_g1a_owner_receipt`.

## Required Signed Receipt Fields

A signed G1a owner receipt candidate must prove:

- schema: `factory-gate-opening-owner-receipt.v1`
- `receipt_kind: gate_opening`
- `receipt_status: signed`
- `gate_id: G1a`
- `gate_name: project_creation`
- `authority_flag: project_creation_allowed_now`
- human owner signature fields: `human_owner_signed`, `owner_name`,
  `owner_signed_at`, and `owner_decision: approve_g1a_opening`
- one-receipt-one-action scope for one not-yet-performed
  `project_workspace_creation`
- bound candidate manifest or candidate packet SHA-256
- independent review receipt reference
- future source-literal opening commit requirement
- future first-use audit requirement
- all protected authority flags false

## Boundary

This intake layer does not sign receipts, mutate source, open
`SOURCE_LITERAL_GATE_OPEN_COMMITS.G1a`, create project workspaces, append
persistent ledgers, write repositories, call connectors, run commands, deploy,
grant protected action authority, grant production PASS, grant enterprise PASS,
or complete Factory Promotion.

If a valid signed owner receipt is supplied, the result can become
`ready_g1a_owner_receipt_for_source_literal_commit`; even then, G1a remains
closed until an isolated source-literal opening commit binds that signed receipt
and the first-use audit is captured.
