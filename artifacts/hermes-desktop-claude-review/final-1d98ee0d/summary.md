## Findings

### 1. P4 Residual dead ternary in projectionRow mirrors the original finding pattern in a different helper

- File: src/desktop-read-model.mjs:510
- Details: While buildReleaseProjection lines 449-450 now hardcode tag_pushed and github_release_published to false (closing the originally flagged dead ternary), projectionRow at src/desktop-read-model.mjs:510 still emits 'authority_open: authorityOpen === true ? false : false'. Both branches resolve to false, so the input is ignored; the intent is clearly 'never trust artifact-supplied authority_open', which is correct and fail-closed, but the redundant ternary is the same code smell that the prior P3 finding called out and could be 'fixed' by a future reader to honor the input.
- Recommendation: Replace 'authority_open: authorityOpen === true ? false : false' with a hardcoded 'authority_open: false' plus a one-line comment that desktop never opens projection-row authority regardless of artifact input. Apply the same shared-list/cleanup discipline used at the buildReleaseProjection site.
- Evidence: Read src/desktop-read-model.mjs:503-514 (projectionRow definition: 'authority_open: authorityOpen === true ? false : false') vs. the cleanup at src/desktop-read-model.mjs:447-450 (tag_pushed, github_release_published explicit false).

### 2. P4 HERMES_REPO_ROOT env override is still not gated or documented in the desktop runbook

- File: apps/desktop/src/main/main.mjs:15
- Details: apps/desktop/src/main/main.mjs:15 ('const REPO_ROOT = process.env.HERMES_REPO_ROOT ?? path.resolve(APP_DIR, "../..")') and apps/desktop/scripts/capture-render.mjs:17 still allow an operator to redirect the shell at an arbitrary directory. The prior review listed this as a residual risk; the candidate hardens preview symlink containment (which closes the main exploit path) but does not document the env override in docs/hermes-desktop-local-launch-runbook-2026-06-14.md and does not gate it to a small allowlist or emit a warning when set. In a single-owner local context this is acceptable, but a future packaged build that inherits an unexpected env value would silently look at the wrong root.
- Recommendation: Either restrict HERMES_REPO_ROOT to an explicit allowlist (and fall back to APP_DIR/../.. otherwise) or document the env variable, its trust expectations, and a recommended unset/sanitize step in docs/hermes-desktop-local-launch-runbook-2026-06-14.md alongside the local launch flow. Mirror any change in apps/desktop/scripts/capture-render.mjs.
- Evidence: Grep 'HERMES_REPO_ROOT' returns only apps/desktop/src/main/main.mjs:15 and apps/desktop/scripts/capture-render.mjs:17; no docs/*.md match. Symlink escape is now blocked by realpath comparison at apps/desktop/src/main/read-model.mjs:60-66 and tested at apps/desktop/test/read-model.test.mjs:211-248, but the env override itself is unchanged.
